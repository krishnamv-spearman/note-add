# Release checklist — Note-Add v1.0.0

Everything here needs **you** (an account, a phone, a decision). The code side of phases 0–7 is done and tested. Work top to bottom; tick as you go. Plan references (P8.x) are in [implementation-plan.md](implementation-plan.md).

Never push to `main` or deploy until step 1 is clear. Nothing in the repo does this for you.

## 0. Before anything: get the code onto GitHub

- [ ] Review the branches `build/phases-0-6` and `build/phase-7` (read [PROGRESS.md](../PROGRESS.md), especially **Decisions to review**). Merge them to `main` (pull request, wait for CI green).
- [ ] CI must be green on `main`: lint, type check, format, unit tests (FC_RUNS=1000), build, bundle budgets, e2e on three projects, base-path e2e, Lighthouse.

## 1. Name check (P8.1) — before the domain

- [ ] Search the Play Store, App Store, the web and the Indian trademark register (ipindia.gov.in) for "Note-Add".
- [ ] Clear → keep the name. Conflict → choose a new name first; it appears in the manifest (`vite.config.ts`, `VitePWA`), `index.html` titles, the icons, the README and the strings "Made by Spearman / Note-Add" in the UI.

## 2. Vercel (P8.2)

- [ ] Create a Vercel project from the GitHub repo. Framework preset **Vite**, build command `npm run build`, output `dist/`. Production branch `main`; every other branch gets a preview URL.
- [ ] Do **not** add environment variables for the default address. Only if you choose `spearman.in/note-add` instead of a subdomain set `VITE_BASE=/note-add/` (see the path option in step 3).
- [ ] Open the first preview URL on your computer and check: the app loads, `/privacy` loads directly (refresh on it), and the response headers include the CSP (browser dev tools → Network → the document → Headers).
- [ ] Record the Vercel address in the README "Deployment" section.

## 3. Domain `notes.spearman.in` (P8.2)

- [ ] In Vercel: Project → Settings → Domains → add `notes.spearman.in`. Vercel shows the DNS record it wants.
- [ ] At the registrar/DNS host for `spearman.in`: add a **CNAME** record, name `notes`, value as shown by Vercel (normally `cname.vercel-dns.com`). Wait for Vercel to show the domain as valid and issue the HTTPS certificate (minutes to hours).
- [ ] Check `https://notes.spearman.in` loads over HTTPS, and `http://` redirects to it.
- [ ] If you chose the path option instead: build with `VITE_BASE=/note-add/`, and have the spearman.in host serve `dist/` under `/note-add/` with the same headers as `vercel.json` (the CSP, and `Cache-Control: no-cache` for `sw.js`) and a fallback of `/note-add/index.html` for unknown paths. `npm run test:e2e:base` already proves the app works under that path.

## 4. Backup fixtures from the real v1.0 app (D47) — do this once, before tagging

The committed fixture `tests/fixtures/backups/v1/valid-3-notebooks-21-pages.json` was generated by the development build, not by a released app. Replace it with one made by the real v1.0 release, then never change it again (every future version must restore it: OLD-01).

- [ ] Open the deployed v1.0 (preview or production) in a fresh browser profile.
- [ ] Build the same data the fixture describes: 3 notebooks, 21 pages in total, including Final pages, a flagged (not-a-number) amount, negative amounts, and pages with a reopened date. The old fixture's content is the reference; open it in a text editor.
- [ ] Settings → **Back up** → save the file.
- [ ] Put it in `tests/fixtures/backups/v1/` under the same name (replace the old file). Run `npm test` and `npm run test:e2e`; fix the tests' expected counts only if your data differs on purpose and say so in the commit message.
- [ ] Commit with a message saying "fixture produced by the released v1.0 app; permanent". From now on, never edit the file.
- [ ] The other fixtures in `tests/fixtures/backups/` (invalid, tampered, and so on) are deliberately broken and stay as they are.

## 5. Production check at the final address (P8.3)

Repeat on the real URL, on the real devices. See the full step-by-step in **PROGRESS.md → Manual tests for you (M7.x)**.

- [ ] HTTPS, no browser warnings; `/privacy` and `/settings` open directly.
- [ ] **Android Chrome:** install (Settings → Install app, or ⋮ → Install app); launch from the home screen icon; works in **airplane mode** (create a notebook, add lines, export a PDF, back up). Make a change in the app, then check the "update ready" prompt appears after a new deployment and does not reload by itself.
- [ ] **iPhone Safari:** the "Install to keep your notes safe" hint shows; Share → Add to Home Screen; launch from the icon; works in **airplane mode**; export a PDF and a JPEG and send them to yourself through the share sheet.
- [ ] **Desktop Chrome or Edge:** install; works offline (turn off Wi-Fi).
- [ ] The offline notice "Note-Add is ready to work offline" appears once on the first visit.
- [ ] Lighthouse (Chrome dev tools, mobile) on the production URL: performance ≥ 90, accessibility ≥ 95, best practices ≥ 90.

## 6. Release (P8.6)

- [ ] Set `"version": "1.0.0"` in `package.json` and `package-lock.json` (the app reads its version and writes it into backups from this). Commit "Release 1.0.0".
- [ ] Tag: `git tag -a v1.0.0 -m "Note-Add 1.0.0"` and push the tag.
- [ ] GitHub → Releases → new release from `v1.0.0` with short notes (what it does, that data stays on the device, the font licences).
- [ ] Make the repository public if it is not (spec §9.1: public repo `note-add` with `CLAUDE.md`, README and font licences).
- [ ] Confirm the licence file and font licences are present (`LICENSE`, `public/fonts/LICENSES/`).

## 7. spearman.in card (P8.5)

- [ ] Add a Note-Add card to the Ventures section of spearman.in: one-line description (for example "A pad of sticky notes for quick money calculations. Works offline, nothing leaves your device."), an **Open the app** button to `https://notes.spearman.in`, and a "Privacy" link to `https://notes.spearman.in/privacy`. Also put the privacy statement text on the card: "Note-Add stores your notes only on your device. Nothing is sent to Spearman or anyone else. Backups and exports go only where you choose to send them."

## 8. User testing with 3–5 people (P8.7)

- [ ] Give no instructions. Task: **create a notebook, fill two pages, export a PDF and send it to yourself.** Time each person (target under 2 minutes) and note where they hesitate or tap the wrong thing.
- [ ] At least one tester on iPhone and one on Android.
- [ ] Anything that blocks the 2-minute task is fixed now (P8.8); everything else becomes a GitHub issue labelled `v1.1`.
- [ ] Add the timings and findings to PROGRESS.md.

## After release

- [ ] Backups made by v1.0 must keep restoring in every later version: that is what the permanent fixture in step 4 protects.
- [ ] Never add analytics, cookies or third-party requests without changing the privacy statement first; the e2e privacy and CSP tests will fail if you do.
